This page is generated from the OpenAPI spec in the repeater project.

- Source file: openhop_repeater/repeater/web/openapi.yaml
- Raw spec URL in this docs site: /openapi/repeater.yaml

Most endpoints require a JWT or API token. Interactive requests can change
configuration, identities, policy, radio state, or transmit on the mesh. Confirm
the selected server and use read-only endpoints first. The public documentation
site does not proxy requests to your Repeater.

Review [Security and Authentication](/projects/openhop-repeater/security-and-authentication/)
before exposing or automating the API.

Current development builds add authenticated neighbour operations for scheduling
a full MQTT publication cycle, reading persisted neighbour scopes, and querying
one zero-hop neighbour. They are documented as `publish_neighbors`,
`neighbor_scopes`, and `query_neighbor_scopes` in the synchronized specification.

The runtime `noise_floor_history` endpoint also accepts `hours`, `limit`, and a
non-negative `offset`. Its response echoes the normalized `limit` and `offset`,
which allows a client to page through dense samples. This pagination is runtime
behavior in the current Repeater `dev` branch even where an older generated API
form shows only the `hours` field.
